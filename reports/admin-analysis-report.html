Category: Security / Routes
File: routes/web.php
Line: 490, 494, 498
Severity: Critical

Description: Public GET routes call Artisan::call('optimize:clear'), Artisan::call('migrate'), and Artisan::call('storage:link').

Why this is a problem: Any visitor can trigger operational commands. Running migrations over HTTP can mutate schema unexpectedly and cause downtime.

Risk: Remote unauthenticated operational control, data/schema corruption, cache invalidation, denial of service.

Recommended Fix: Remove these routes from production. If retained locally, protect with signed URL, environment guard, auth, and super-admin authorization.

Route::middleware(['auth', 'role:super_admin'])
    ->get('migrate', fn () => abort_unless(app()->environment('local'), 404));

Category: Authorization
File: routes/web.php
Line: 286
Severity: Critical

Description: The entire Admin module is inside ['auth', 'role:admin', 'billing.check'].

Why this is a problem: All admins can access finance, salary, student records, account resets, logs, settings, certificates, and admission actions.

Risk: Privilege escalation inside the admin role, unauthorized salary/payment changes, privacy exposure.

Recommended Fix: Add policies/gates or permission middleware per feature and call $this->authorize() inside mutating Livewire actions.

Route::get('salary/payment', PaymentComponent::class)
    ->middleware('can:salary.manage')
    ->name('admin.salary.payment');

Category: Security / Validation
File: app/Livewire/Admin/Student/StudentAccountComponent.php; mirrored in Parent/Employee account components
Line: 85, 89
Severity: High

Description: Password reset accepts min:4. Password state is public and mutable on the component.

Why this is a problem: Four-character credentials are trivial to guess, and public Livewire properties are serialized between requests.

Risk: Account takeover, credential stuffing success, accidental exposure in Livewire payloads or logs.

Recommended Fix: Use Laravel password defaults, confirmation, temporary-password flows, and force password reset on next login.

'password' => ['required', 'confirmed', Password::defaults()],
$this->user->forceFill(['password' => Hash::make($this->password)]);

Category: Validation / Security
File: app/Livewire/Admin/Student/StudentAddComponent.php
Line: 181, 193
Severity: High

Description: Upload fields are only nullable while files are stored on the public disk.

Why this is a problem: Non-image files can be accepted by the component and exposed under public storage.

Risk: Stored malicious content, storage abuse, broken rendering, privacy leaks.

Recommended Fix: Add image/MIME/size rules and use private disks for sensitive documents.

'student_photo_upload' => ['nullable', 'image', 'mimes:jpg,jpeg,png,webp', 'max:2048'],
'guardian_photo_upload' => ['nullable', 'image', 'mimes:jpg,jpeg,png,webp', 'max:2048'],

Category: Performance
File: app/Livewire/Admin/DashboardComponent.php
Line: 76-471
Severity: High

Description: The dashboard builds many counts, sums, joins, recent lists, and chart queries one by one.

Why this is a problem: First page load becomes database-bound and hard to cache or test.

Risk: Slow Admin dashboard, lock contention during peak usage, poor scalability.

Recommended Fix: Move statistics to a dashboard service, cache per institution, and combine aggregate queries where practical.

Cache::remember("admin-dashboard:$institutionId", now()->addMinutes(5), fn () =>
    app(AdminDashboardStats::class)->forInstitution($institutionId)
);

Category: Security / Query Hardening
File: app/Livewire/Admin/OfficeAccounting/TransactionComponent.php
Line: 43, 132
Severity: Medium

Description: $sortField is a public Livewire property and is used in orderBy().

Why this is a problem: Livewire clients can mutate public properties. Laravel protects bindings, but identifier input must still be allowlisted.

Risk: SQL errors, unexpected ordering, possible query manipulation depending on driver behavior.

Recommended Fix: Allowlist columns before assigning sort state.

private array $sortable = ['date', 'voucher_no', 'amount', 'type'];
abort_unless(in_array($field, $this->sortable, true), 403);

  • Authorization is mostly route-role based; no Admin feature policies were found in the scoped review.
  • Unauthenticated maintenance routes in routes/web.php are the most urgent security issue.
  • Payment callback CSRF exclusions require strict gateway signature validation in controllers.
  • Raw certificate rendering is intentional for templates but must be restricted/sanitized because template content is rendered with {!! !!}.
  • Weak/default password workflows exist in Admin account creation/reset paths.

  • Dashboard statistics should be cached or pre-aggregated per institution.
  • Ledger running balances currently load all rows every render; use SQL window functions, cached ledger snapshots, or paginated balance calculation.
  • Date filtering with DATE_FORMAT() should be replaced by whereBetween() ranges.
  • Several views use wire:model.live on many inputs; reserve live updates for dependent fields and search controls.
  • Dynamic sale item views should pre-index products by category in the component instead of calling collection lookups in Blade loops.

  • Several unique keys are global where the domain is institution-scoped: students, registration numbers, product codes.
  • guardian_student needs a unique composite key to prevent duplicate relationships.
  • Query-heavy filters need composite indexes such as (institution_id, created_at), (institution_id, payment_date), and (institution_id, status).
  • Foreign-key validation in forms should include institution scoping, not only exists:table,id.

  • Unused files: resources/views/livewire/admin/exam/exam-setup-component.blade copy.php appears to be a backup copy.
  • Possibly unused component: app/Livewire/Admin/Academic/CategoryComponent.php has no matching Admin route in routes/web.php.
  • Unused imports: Illuminate\Validation\ValidationException appears in some components without use.
  • Dead comments: Several files contain old commented code and mojibake comments, which reduce maintainability.

  1. Remove or protect unauthenticated maintenance routes.
  2. Add granular policies/gates for finance, salary, settings, account resets, and logs.
  3. Harden payment callback verification before relying on CSRF exceptions.
  4. Replace default and four-character passwords with Laravel password defaults.
  5. Validate all Admin uploads with MIME, image, and size rules.
  6. Sanitize or tightly restrict raw certificate template HTML.
  7. Replace User::$guarded = [] with explicit fillable fields.
  8. Allowlist all Livewire sort fields before passing to orderBy().
  9. Scope all exists validation to the current institution.
  10. Cache or consolidate Admin dashboard statistics.
  11. Replace DATE_FORMAT() filters with range queries.
  12. Move ledger running balance logic out of render-time all-row loading.
  13. Add unique key to guardian_student.
  14. Change global unique student/product keys to institution-scoped composite uniqueness where business rules allow.
  15. Add composite indexes for common institution/date/status filters.
  16. Split large Livewire components into services and smaller form objects/actions.
  17. Normalize Admin routes into an admin prefix/name group or dedicated route file.
  18. Remove backup Blade file from resources.
  19. Pre-index product/category collections for dynamic inventory forms.
  20. Add focused tests for authorization, upload validation, account reset, and payment posting.
